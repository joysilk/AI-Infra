# 03-03. 클라우드 (AWS 중심 + GCP/Azure 비교)

> 한국 시장은 AWS가 가장 크고, 이어서 Azure(공공/엔터프라이즈), GCP(스타트업/데이터·ML), 국내 클라우드(네이버클라우드, KT, NHN)가 있습니다. **AWS를 깊게, 나머지는 이름 대응표로 이해**하는 전략을 추천합니다.

## 1. 개념 설명

### 1-1. 클라우드 기본 개념
- **IaaS**(서버·네트워크를 빌림: EC2), **PaaS**(실행 환경 제공: Elastic Beanstalk, App Engine), **SaaS**(완성 서비스: Gmail).
- **리전(Region)**: 지리적 위치(서울 `ap-northeast-2`). **AZ(가용 영역)**: 한 리전 안의 독립된 데이터센터 묶음 → 여러 AZ에 나눠 배치하면 한 곳이 죽어도 서비스 유지.
- **공동 책임 모델**: 클라우드 사업자는 "클라우드 자체의 보안", 사용자는 "클라우드 위에서 설정한 것의 보안"(IAM, 데이터, OS 패치 등).
- **탄력성**: 필요할 때 늘리고(scale-out) 줄이는 것. 과금: 사용량(초/시간/GB/요청).
- **Well-Architected 6대 축**: 운영 우수성, 보안, 신뢰성, 성능 효율성, 비용 최적화, 지속 가능성.

### 1-2. AWS 핵심 서비스

**컴퓨팅**
- **EC2**: 가상 서버. 인스턴스 타입(t3=범용 버스트, m=범용, c=CPU, r=메모리, g/p=GPU). 구매 옵션: On-Demand, Reserved/Savings Plans, Spot(최대 90% 저렴, 중단 가능). AMI(서버 이미지), 키페어, 사용자 데이터(부팅 스크립트), EBS(블록 디스크).
- **Auto Scaling Group(ASG)**: 부하에 따라 EC2 개수 자동 조절. Launch Template.
- **Lambda**: 서버 없이 함수 실행(이벤트 기반, 15분 제한). **ECS/Fargate**: 컨테이너 실행(Fargate는 서버 관리 불필요). **EKS**: 관리형 Kubernetes.

**스토리지**
- **S3**: 객체 저장소. 버킷, 스토리지 클래스(Standard/IA/Glacier), 버전 관리, 수명 주기 정책, 암호화, 퍼블릭 액세스 차단. 내구성 99.999999999%.
- **EBS**(블록, 한 AZ), **EFS**(공유 NFS 파일), **FSx**.

**데이터베이스**
- **RDS**(MySQL/PostgreSQL 등 관리형: 백업, 멀티 AZ 장애조치, 읽기 복제본), **Aurora**(고성능 호환 DB), **DynamoDB**(NoSQL), **ElastiCache**(Redis/Memcached).

**네트워크**
- **VPC, 서브넷, IGW, NAT GW, 보안그룹, NACL**, **ELB**(ALB/NLB/GWLB), **Route53**(DNS), **CloudFront**(CDN), **VPC Endpoint**(인터넷 없이 AWS 서비스 접근), **Transit Gateway**, **VPN/Direct Connect**.

**보안/ID**
- **IAM**: 사용자/그룹/역할/정책(JSON). **STS**(임시 자격 증명), **KMS**(암호화 키), **Secrets Manager/SSM Parameter Store**, **ACM**(인증서), **WAF/Shield**, **GuardDuty**(위협 탐지), **CloudTrail**(API 호출 기록), **Config**(설정 변경 기록).

**관리/관측**
- **CloudWatch**(지표·로그·알람), **Systems Manager**, **CloudFormation**(AWS IaC), **Organizations**(멀티 계정), **Cost Explorer/Budgets**.

**통합/기타**
- **SQS**(큐), **SNS**(알림), **EventBridge**(이벤트 버스), **API Gateway**, **Step Functions**.

### 1-3. 서비스 대응표
| 분류 | AWS | GCP | Azure |
|---|---|---|---|
| 가상 서버 | EC2 | Compute Engine | Virtual Machines |
| 오브젝트 스토리지 | S3 | Cloud Storage | Blob Storage |
| 관리형 K8s | EKS | GKE | AKS |
| 서버리스 함수 | Lambda | Cloud Functions/Run | Functions |
| 관리형 RDB | RDS/Aurora | Cloud SQL/AlloyDB | Azure SQL/Database for PostgreSQL |
| NoSQL | DynamoDB | Firestore/Bigtable | Cosmos DB |
| 가상 네트워크 | VPC (리전 단위) | VPC (글로벌) | VNet |
| DNS | Route53 | Cloud DNS | Azure DNS |
| IAM | IAM(역할/정책) | IAM(프로젝트/역할) | Entra ID + RBAC |
| 모니터링 | CloudWatch | Cloud Monitoring | Azure Monitor |
| IaC | CloudFormation | Deployment Manager | ARM/Bicep |
| 데이터웨어하우스 | Redshift | BigQuery | Synapse |
| ML 플랫폼 | SageMaker | Vertex AI | Azure ML |
| 계정 구조 | Account/Organizations | Project/Folder/Org | Subscription/Management Group |
- 차이 포인트: GCP VPC는 글로벌, GKE 성숙도 높음, BigQuery 강점. Azure는 Windows/AD(Entra) 연동과 엔터프라이즈 강점.

### 1-4. 비용 개념
- 과금 함정: NAT Gateway 데이터 처리비, 데이터 전송(아웃바운드), 미사용 EBS/EIP, 로그 보존, RDS 멀티 AZ 2배.
- 절감: 라이트사이징, Savings Plans, Spot, 스토리지 수명주기, 개발 환경 야간 정지.

## 2. 공부 순서
1. 계정 보안/IAM/Budgets → 2. EC2·EBS·S3 → 3. VPC → 4. ELB·ASG → 5. RDS·Route53·CloudFront → 6. CloudWatch·CloudTrail → 7. Lambda·SQS·SNS → 8. ECS/EKS 개요 → 9. 멀티 계정·SSO·Organizations → 10. 비용 최적화/Well-Architected → 11. GCP/Azure 대응표 읽기, 필요 시 1개 서비스씩 체험.
- 기간: 집중 5주 + SAA 시험 준비 2~3주.

## 3. 실습 과제
1. 계정 초기 보안: 루트 MFA, 관리자 IAM Identity Center 사용자, Budgets 알림.
2. S3 정적 웹 호스팅 + CloudFront + HTTPS + 커스텀 도메인.
3. 3-tier: ALB → EC2(ASG, 프라이빗) → RDS(프라이빗), 보안그룹 체인(ALB SG → 앱 SG → DB SG).
4. EC2 역할(Instance Profile)로 S3 접근 (액세스 키 없이).
5. Lambda + S3 이벤트로 이미지 썸네일 생성, SNS 알림.
6. CloudTrail로 "누가 SG를 열었나" 추적, CloudWatch 알람 → SNS 이메일.
7. 비용 보고서 보고 가장 비싼 항목 3개 설명하고 절감안 제시.
8. (심화) 한 서비스를 다른 AZ로 장애 주입(인스턴스 종료)해 ASG 복구 확인. RDS 스냅샷 복구.
9. (비교) 같은 정적 사이트를 GCP Cloud Storage 또는 Azure Blob 정적 호스팅에도 올려 보기.
