# 02-1. 5년차까지 연차별 로드맵

> 원칙: **넓게 얕게 → 한 영역 깊게 → 설계/리드**. 매년 "새 도구 N개"가 아니라 "문제 N개를 끝까지 해결"에 초점.
> 0년차 상세 26주 계획은 [02-2](02-2-0년차-26주-계획.md) 참고.

## 한눈에 보기
| 연차 | 키워드 | 한 줄 목표 |
|---|---|---|
| 0년차 | 준비기 | 기초 다지고 포트폴리오 3개 + 자격증 1~2개로 취업 |
| 1년차 | 따라 하기 | 시킨 일을 안전하게 수행, 운영 절차 체득 |
| 2년차 | 혼자 하기 | 작은 기능/환경을 처음부터 끝까지 담당 |

| 4년차 | 설계하기 | 아키텍처 설계, 비용/보안/가용성 트레이드오프 판단 |
| 5년차 | 이끌기 | 팀 단위 문제 정의·표준화·후배 성장·비즈니스 연결 |

## 0년차: 준비기 (취업 준비 6~9개월)
- **갖춰야 할 실력**: Linux 터미널로 서버 직접 설정, TCP/IP·DNS·HTTP 설명 가능, AWS 핵심 서비스 직접 구축, Docker 빌드·실행, Git 협업, Python/Bash로 간단한 자동화.
- **공부할 기술**: Linux → 네트워크 → Git/Bash/Python → AWS → Docker → Terraform → CI/CD → Kubernetes 입문 → 모니터링 기초.
- **해볼 프로젝트**: 04번의 1~5번(정적 웹 호스팅, 3-tier VPC, Docker 컨테이너화, Terraform 인프라, CI/CD 파이프라인).
- **자격증**: AWS SAA(필수급), 리눅스마스터 2급 또는 정보처리기사(상황에 따라), 여력 있으면 Terraform Associate.
- **회사에서 맡게 될 일**: (입사 전) 해당 없음. 인턴/부트캠프/스터디로 협업 경험 쌓기.
- **다음 단계 체크리스트**
  - [ ] 빈 서버에 SSH 접속해 웹서버 설치·방화벽·서비스 등록·로그 확인 가능
  - [ ] "브라우저에 URL 입력하면 벌어지는 일"을 5분 안에 설명
  - [ ] VPC/서브넷/IGW/NAT/보안그룹을 그림으로 설명
  - [ ] Dockerfile 작성, 이미지 줄이기, compose로 다중 컨테이너 실행
  - [ ] Terraform으로 인프라 생성·삭제(`apply/destroy`) 반복 가능
  - [ ] GitHub Actions로 테스트→빌드→배포 자동화
  - [ ] 포트폴리오 3개 이상 + README 완성, AWS SAA 취득
  - [ ] 이력서 제출 30곳 이상, 면접 질문 60개 답변 연습

## 1년차: 운영 기본기와 신뢰 쌓기
- **갖춰야 할 실력**: 운영 환경에서 **실수하지 않는 습관**(변경 전 백업, 롤백 계획, 작업 전후 확인), 티켓/장애 알림 대응, 기존 코드/문서 읽기, 질문하는 법.
- **공부할 기술**: 회사 스택 파악이 최우선. 일반적으로 Linux 심화(성능, 로그 분석), AWS 운영(CloudWatch, IAM, 비용), Kubernetes 기본 운영(`kubectl`, 배포, 로그), Terraform 모듈 읽기/수정, Prometheus·Grafana 대시보드.
- **해볼 프로젝트**: 회사 업무 내에서 ① 수동 작업 1개 자동화 스크립트 ② 대시보드/알림 1개 개선 ③ 운영 가이드(Runbook) 3개 작성. 개인: 홈랩 쿠버네티스(k3s) 운영.
- **자격증**: AWS SAA(미취득 시), CKA 준비 시작(실무에 K8s 있으면).
- **회사에서 맡게 될 일**: 계정/권한 발급, 서버·컨테이너 배포 보조, 모니터링 확인, 장애 1차 대응, 정기 패치, 비용 리포트 작성 보조.
- **체크리스트**
  - [ ] 선임 도움 없이 일반적인 알림(디스크, CPU, 5xx) 1차 원인 파악
  - [ ] 변경 작업을 티켓·PR·롤백 계획과 함께 수행
  - [ ] 회사 아키텍처를 그림으로 설명 가능
  - [ ] Runbook 3개 이상 작성, 작업 실수 0건(큰 사고 없음)
  - [ ] 온콜 부사수 경험

## 2년차: 한 영역을 맡아서 끝까지
- **갖춰야 할 실력**: 요구사항을 받아 **설계 초안→구현→검증→문서화** 수행. IaC로 모든 변경 관리. 장애 시 스스로 원인 가설 세워 검증.
- **공부할 기술**: Terraform 모듈화·상태(state) 관리, Kubernetes 심화(Ingress, HPA, PV, RBAC, Helm), ArgoCD(GitOps), 로그 파이프라인(Loki/ELK), 네트워크 심화(Transit Gateway, VPN, 로드밸런서 튜닝), 보안 기본(IAM 최소권한, Secrets Manager/Vault).
- **프로젝트**: 회사에서 신규 서비스 환경 1개를 처음부터 구축, 또는 CI/CD 개편. 개인: 포트폴리오 6~8번(GitOps, 관측성 스택).
- **자격증**: CKA(권장), Terraform Associate, AWS DevOps Professional 또는 SA Professional 검토.
- **업무**: 신규 환경 구축, 파이프라인 유지, 장애 2차 대응, 비용 절감 과제, 후배/인턴 온보딩 보조.
- **체크리스트**
  - [ ] 한 서비스의 인프라 전체를 코드로 재현 가능
  - [ ] 장애 포스트모템 1회 이상 작성
  - [ ] 배포 시간/실패율 같은 수치로 개선 성과를 말할 수 있음
  - [ ] 한 영역(예: K8s, CI/CD, 모니터링 중 하나)에서 팀 내 "물어보면 되는 사람"

## 3년차: 구조적 개선과 전문 분야 선택
- **갖춰야 할 실력**: 증상이 아니라 **근본 원인**을 제거. SLI/SLO 개념으로 신뢰성 측정. 비용·성능 병목 분석. 분기점(SRE/플랫폼/클라우드 아키텍트/MLOps) 선택.
- **공부할 기술**: SRE 방법론(에러 버짓, 토일 제거), 관측성(OpenTelemetry, 분산 추적), 용량 계획, 멀티 계정/멀티 클러스터, 서비스 메시(Istio 개요), 정책(OPA/Kyverno), 선택 분야 심화(MLOps라면 Kubeflow/GPU 스케줄링).
- **프로젝트**: SLO 도입, 비용 20% 절감, 배포 파이프라인 표준 템플릿화, 장애 훈련(Game Day).
- **자격증**: AWS SA Professional/DevOps Professional, CKS(보안), 필요 시 클라우드 보안/ML 관련.
- **업무**: 서비스 단위 오너십, 온콜 로테이션 중심, 아키텍처 리뷰 참여, 신입 멘토링.
- **체크리스트**
  - [ ] 숫자로 증명되는 개선 사례 3개 이상(이전→이후)
  - [ ] SLO 정의와 알림 체계 개선 경험
  - [ ] 큰 장애의 근본 원인과 재발 방지책을 주도
  - [ ] 전문 분야 1개를 정함

## 4년차: 설계와 의사결정
- **갖춰야 할 실력**: 가용성·보안·비용·운영 복잡도 **트레이드오프**를 문서(ADR)로 설명하고 설득. DR(재해복구) 설계. 팀 외부와 협상.
- **공부할 기술**: 멀티 리전/DR 전략, 대규모 쿠버네티스 운영(업그레이드, 멀티 테넌시), 플랫폼 설계(셀프서비스), 보안 컴플라이언스(ISMS-P 개요), FinOps.
- **프로젝트**: 멀티 AZ/리전 설계, 플랫폼 표준(골든 패스) 구축, 마이그레이션 리드, 보안 감사 대응.
- **자격증**: 필수 아님. 학습 목적으로 전문 자격(AWS Pro, CKS 등) 보완.
- **업무**: 설계 리드, 기술 선정(PoC), 예산/비용 책임, 주니어 코칭, 타 팀과 협업 프로젝트.
- **체크리스트**
  - [ ] ADR(아키텍처 결정 기록) 5개 이상 작성
  - [ ] DR 훈련 실제 수행
  - [ ] 기술 선정 근거를 비개발자(PM/경영진)에게 설명 가능
  - [ ] 후배 1~2명이 성장한 사례

## 5년차: 팀을 이끄는 엔지니어
- **갖춰야 할 실력**: 문제 정의 → 우선순위 → 실행 → 측정. 기술 로드맵, 인력/예산 감각, 문화(포스트모템·블레임리스) 정착. 개인 기여자(IC)와 리드 중 방향 결정.
- **공부할 기술**: 선택 분야 최상위(플랫폼 설계, 대규모 신뢰성, 보안 아키텍처, MLOps 인프라), 조직/커뮤니케이션, 계약/벤더 협상, 기술 글쓰기.
- **프로젝트**: 연간 인프라 로드맵 수립, 조직 단위 표준화, 대규모 마이그레이션 완수, 기술 블로그/발표.
- **자격증**: 선택. 오히려 발표·글·오픈소스 기여가 신호.
- **업무**: 팀 리드/테크 리드, 채용 면접관, 장애 지휘관(Incident Commander), 설계 승인.
- **5년차 체크리스트(졸업 기준)**
  - [ ] 새로운 문제를 정의하고 해결 방안을 스스로 설계·제안
  - [ ] 장애 지휘 및 포스트모템 문화 주도
  - [ ] 비용/보안/가용성 지표를 개선하고 경영진에 보고
  - [ ] 후배를 키우고 면접관으로 참여
  - [ ] 외부 신호(발표, 블로그, 오픈소스 중 1개 이상)
