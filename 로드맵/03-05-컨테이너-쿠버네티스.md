# 03-05. 컨테이너(Docker)와 오케스트레이션(Kubernetes)

## 1. 개념 설명

### 1-1. 컨테이너와 Docker
- **컨테이너**: 앱과 실행에 필요한 라이브러리를 한 묶음으로 격리해 실행하는 기술. 가상머신(VM)과 달리 OS 커널을 공유해 가볍고 빠름. 핵심 기술: **namespace**(격리), **cgroup**(자원 제한), 이미지 레이어(overlay filesystem).
- **이미지**: 컨테이너 실행 설계도(읽기 전용 레이어). **컨테이너**: 이미지를 실행한 인스턴스. **레지스트리**: 이미지 저장소(Docker Hub, ECR, GHCR).
- **Dockerfile** 핵심: `FROM`, `WORKDIR`, `COPY`, `RUN`, `ENV`, `EXPOSE`, `CMD` vs `ENTRYPOINT`.
- 좋은 이미지: 작은 베이스(alpine/distroless/slim), 멀티스테이지 빌드, 레이어 캐시 순서(변경 적은 것 먼저), 비루트 사용자, `.dockerignore`, 태그에 `latest` 지양(버전/커밋 해시), 취약점 스캔(Trivy).
```dockerfile
FROM python:3.12-slim AS base
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
USER 1000
CMD ["gunicorn","-b","0.0.0.0:8000","app:app"]
```
- 데이터: 컨테이너는 휘발성 → **볼륨/바인드 마운트**. 네트워크: bridge/host, 컨테이너 이름으로 통신. **Docker Compose**: 여러 컨테이너를 yaml 하나로.
- 로그: stdout/stderr로 출력(12-Factor). 설정: 환경변수.

### 1-2. Kubernetes (K8s)
- **Kubernetes**: 컨테이너 여러 개를 여러 서버에 자동 배치·복구·확장하는 오케스트레이터.
- **구조**: Control Plane(API Server, etcd, Scheduler, Controller Manager) + Worker Node(kubelet, kube-proxy, 컨테이너 런타임).
- **핵심 오브젝트**
  - **Pod**: 컨테이너 묶음의 최소 단위. 죽으면 새로 만들어짐(IP 바뀜).
  - **Deployment/ReplicaSet**: 원하는 Pod 개수 유지, 롤링 업데이트, 롤백.
  - **Service**: Pod 묶음 앞의 고정 접점(ClusterIP, NodePort, LoadBalancer).
  - **Ingress**(+Controller): HTTP 라우팅(호스트/경로).
  - **ConfigMap/Secret**: 설정/비밀값 분리(Secret은 기본적으로 base64일 뿐 암호화 아님 → 외부 시크릿 연동 권장).
  - **PV/PVC/StorageClass**: 영구 저장소. **StatefulSet**: 순서·고정 ID가 필요한 앱(DB). **DaemonSet**: 노드마다 1개(로그 수집기). **Job/CronJob**: 일회성/주기 작업.
  - **Namespace**, **RBAC**(권한), **NetworkPolicy**(Pod 간 통신 제한), **ServiceAccount**.
  - **HPA**(Pod 수 자동 조절), **VPA**, **Cluster Autoscaler/Karpenter**(노드 수).
  - **resources requests/limits**: requests=스케줄링 기준 최소 보장, limits=최대. 메모리 limit 초과 시 OOMKilled, CPU는 스로틀링.
  - **Probes**: liveness(죽었나→재시작), readiness(트래픽 받을 준비 됐나), startup.
  - **스케줄링 제어**: nodeSelector, affinity, taint/toleration, PodDisruptionBudget, topologySpread.
- **배포 도구**: `kubectl`, **Helm**(패키지/템플릿), **Kustomize**(오버레이). 배포 전략: Rolling, Blue/Green, Canary.
- **관리형**: EKS/GKE/AKS. 직접 구축: kubeadm, k3s, kind(로컬).
- **디버깅 순서**: `kubectl get pods` → `describe pod`(이벤트) → `logs [-p]` → `exec` → 노드/네트워크. 흔한 상태: `Pending`(자원 부족/스케줄 불가), `CrashLoopBackOff`(앱 크래시), `ImagePullBackOff`(이미지/인증), `OOMKilled`.

## 2. 공부 순서
Docker: 이미지/컨테이너 → Dockerfile → 볼륨/네트워크 → Compose → 최적화/보안 → ECR.
K8s: 아키텍처 개념 → Pod/Deployment/Service → ConfigMap/Secret → Ingress → 볼륨 → probes/resources/HPA → RBAC/NetworkPolicy → Helm → 클러스터 운영(업그레이드, 노드 관리) → GitOps(ArgoCD) → (선택) 서비스 메시, Operator.
- 기간: Docker 2주, K8s 입문 3주 + 심화 지속. CKA 준비 시 6~10주.

## 3. 실습 과제
1. 간단한 웹앱 컨테이너화 → 이미지 크기를 1GB → 100MB대로 줄이기(멀티스테이지/슬림).
2. compose로 웹+DB+Redis, 볼륨으로 데이터 유지 확인.
3. 컨테이너를 메모리 64MB로 제한해 OOM 재현(`--memory`).
4. kind/k3s에 앱 배포 → 이미지 업데이트(롤링) → 잘못된 이미지 배포 후 `rollout undo`.
5. Ingress로 경로 기반 라우팅 2서비스, TLS(cert-manager) 적용.
6. HPA: 부하 생성(`hey`/`k6`)으로 Pod 증가 관찰.
7. liveness/readiness 일부러 실패시켜 동작 차이 관찰.
8. RBAC: 특정 네임스페이스 읽기 전용 사용자 만들기.
9. Helm 차트 직접 작성, values로 환경 분리.
10. (심화) 노드 drain, 클러스터 업그레이드, etcd 백업/복구(CKA 대비).
11. (심화) EKS를 Terraform으로 올리고 ALB Controller, ExternalDNS, Karpenter 적용(비용 주의, 실습 후 삭제).
