# 03-09. 보안 (IAM 설계, 비밀값 관리, 네트워크 보안)

> 인프라 엔지니어의 보안은 "해킹 기법"보다 **사고가 나지 않게 구조를 만들고, 났을 때 피해를 줄이는 설계**입니다.

## 1. 개념 설명

### 1-1. 기본 원칙
- **최소 권한(Least Privilege)**: 필요한 최소한의 권한만. **심층 방어(Defense in Depth)**: 방어선을 여러 겹. **Zero Trust**: 내부망이라고 믿지 않고 항상 검증. **공동 책임 모델**. **CIA**: 기밀성·무결성·가용성. **Shift-left**: 개발 초기에 보안 점검.

### 1-2. IAM 설계 (AWS 기준)
- 구성: **사용자**(사람/장기 키), **그룹**, **역할**(임시 자격, 서비스·교차 계정에 사용), **정책**(JSON 권한 문서), **신뢰 정책**(누가 역할을 맡을 수 있나), **권한 경계**, **SCP**(Organizations 단위 상한).
- 정책 평가: 기본 거부 → 명시적 허용 필요 → **명시적 Deny가 항상 우선**.
- 모범 사례:
  - 루트 계정은 MFA, 일상 사용 금지, 액세스 키 삭제.
  - 사람은 **IAM Identity Center(SSO)** + 임시 자격 증명. 장기 액세스 키는 지양.
  - 서비스(EC2/Lambda/Pod)는 **역할**(Instance Profile, IRSA/Pod Identity). 코드에 키 하드코딩 금지.
  - 멀티 계정 전략: prod/dev/보안/로그 계정 분리, Organizations + SCP 가드레일.
  - `*` 와일드카드 지양, 리소스·조건(Condition, 예: 출발 IP/MFA/태그) 지정. IAM Access Analyzer로 과도 권한 점검, 미사용 권한 제거.
  - 직무 기반 역할(읽기 전용, 운영, 관리자), 승인 기반 임시 상승(break-glass 계정은 감사 알림).
- 최소 권한 정책 예:
```json
{"Version":"2012-10-17","Statement":[{
  "Effect":"Allow",
  "Action":["s3:GetObject"],
  "Resource":"arn:aws:s3:::my-app-bucket/reports/*"
}]}
```
- Kubernetes: RBAC(Role/ClusterRole/Binding), ServiceAccount, 최소 권한, `cluster-admin` 남발 금지.

### 1-3. 비밀값(Secret) 관리
- 비밀값: 비밀번호, API 키, 토큰, 인증서, DB 접속 정보.
- 금지: 소스코드, Git, 이미지, 슬랙/메신저, 평문 환경변수 파일.
- 도구: **AWS Secrets Manager**(자동 교체, 비용 있음), **SSM Parameter Store**(저렴), **HashiCorp Vault**(동적 시크릿·범용), **SOPS + KMS/age**(암호화된 채로 Git 저장), **Sealed Secrets/External Secrets Operator**(쿠버네티스), CI는 OIDC로 키 없이.
- 원칙: 최소 권한 접근, **정기 교체(rotation)**, 감사 로그, 유출 시 즉시 폐기→교체→사용 이력 조사.
- **KMS**: 암호화 키 관리. 전송 중(TLS) + 저장 시(EBS, S3, RDS 암호화) 암호화. 봉투 암호화(envelope encryption) 개념.

### 1-4. 네트워크 보안
- 구조: 퍼블릭(ALB/NAT만) / 프라이빗(앱) / 격리(DB) 서브넷 분리. 보안그룹은 **참조 체인**(ALB SG → 앱 SG → DB SG), 0.0.0.0/0 인바운드 최소화(특히 22/3389/DB 포트).
- 관리자 접속: 배스천 대신 **SSM Session Manager**(포트 열지 않음), VPN, 제로 트러스트 접근.
- **VPC Endpoint**로 AWS 서비스 접근을 인터넷 없이. **NACL**은 보조적 차단. VPC Flow Logs로 트래픽 기록.
- 엣지: **WAF**(SQL 인젝션·XSS 등 L7 필터), **Shield/DDoS 방어**, CDN, 레이트 리밋.
- TLS 어디서나, 최신 TLS 버전, 인증서 자동 갱신(ACM, cert-manager).
- 쿠버네티스: NetworkPolicy(기본 deny), Pod Security Standards(특권 컨테이너 금지, 비루트), 이미지 서명/스캔, 런타임 탐지(Falco), 노드 접근 최소화.
- 서버: SSH 키만 허용, root 로그인 금지, 정기 패치, fail2ban, CIS 벤치마크, SELinux/AppArmor.

### 1-5. 탐지·감사·대응
- **CloudTrail**(API 감사), **Config**(설정 변경/규정 준수), **GuardDuty**(이상 행위 탐지), **Security Hub**, VPC Flow Logs, 중앙 로그 계정에 불변 저장. 이상 징후(루트 로그인, 새 액세스 키 생성, SG 전체 개방) 알림.
- 취약점 관리: 의존성/이미지 스캔(Trivy, Dependabot), 패치 주기, IaC 스캔(Checkov).
- 컴플라이언스(한국): ISMS-P, 개인정보보호법, 금융/공공 망분리 규정(해당 시). 로그 보관 기간 요구 확인.
- 사고 대응: 격리 → 증거 보존 → 원인 분석 → 키 교체/복구 → 사후 개선. 자격 증명 유출은 항상 "폐기 + 사용 이력 조사"가 선행.

## 2. 공부 순서
IAM 기본(사용자/역할/정책) → 정책 읽기/작성 → MFA/SSO → 보안그룹·VPC 설계 → 암호화(KMS/TLS) → Secrets Manager/SSM → CloudTrail/GuardDuty → 쿠버네티스 RBAC/NetworkPolicy → IaC·이미지 스캔 → 멀티 계정·SCP → 컴플라이언스 개요.
- 기간: 3주 + 상시. 자격증(SAA 보안 파트, 이후 CKS/AWS Security Specialty) 연계.

## 3. 실습 과제
1. 신규 계정 보안 체크리스트 수행(루트 MFA, 키 삭제, Budgets, CloudTrail 활성화).
2. S3 버킷 하나에만 읽기 가능한 역할 작성, `Access Denied` 사례를 일부러 만들고 정책 시뮬레이터로 원인 분석.
3. EC2 Instance Profile로 키 없이 S3 접근, 코드에 키가 없음을 증명.
4. 비밀값을 Secrets Manager에 저장하고 Lambda/앱에서 조회, 교체 정책 설정.
5. SOPS로 암호화한 시크릿 파일을 Git에 커밋하고 CI에서 복호화.
6. SSM Session Manager로 SSH 포트를 열지 않고 접속.
7. 보안그룹 `0.0.0.0/0:22`를 찾아 알려주는 Config 규칙/스크립트.
8. GitHub 저장소에 gitleaks 적용, 실수로 올린 키 탐지 시나리오와 대응 절차 문서화.
9. 쿠버네티스 NetworkPolicy로 DB Pod는 앱 Pod에서만 접근 가능하게.
10. (심화) SCP로 특정 리전 외 사용 금지, CloudTrail 이상 징후 알림.
