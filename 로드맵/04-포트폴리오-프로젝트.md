# 04. 포트폴리오 프로젝트 (10개, 쉬운 것부터 어려운 것까지)

## 공통 원칙
1. **결과가 아니라 "왜 그렇게 설계했나"와 "무엇이 터졌고 어떻게 고쳤나"**가 포트폴리오의 핵심.
2. 모든 프로젝트는 GitHub 저장소 1개 + README + 아키텍처 다이어그램(draw.io, Excalidraw, Mermaid) + 재현 방법.
3. **비용 안전장치**: AWS Budgets($5~10 알림), 실습 후 `terraform destroy`, 태그 `project=...`, NAT Gateway/ALB/EKS/RDS는 시간당 과금 → 실습 시간만 켜기. 계정 크레딧/프리 티어 조건은 시점별로 달라지므로 공식 안내 확인.
4. 시크릿 커밋 금지(gitleaks 적용). 라이선스(MIT) 표기.
5. 숫자로 증명: 이미지 크기 1.1GB→95MB, 배포 시간 12분→4분, 월 비용 $X.

## README 공통 템플릿
```
# 프로젝트명
한 줄 요약 / 해결하려는 문제
## 아키텍처 (다이어그램 이미지)
## 사용 기술 (표)
## 주요 설계 결정과 이유 (Trade-off)
## 재현 방법 (명령어 순서, 필요 조건)
## 결과 (스크린샷, 수치)
## 트러블슈팅 기록 (문제 → 원인 → 해결)
## 비용 (예상 월 비용 / 절감 방법)
## 개선 계획
```

## 프로젝트 1. [난이도 ★☆☆☆☆] S3 + CloudFront 정적 웹사이트 호스팅
- **목표**: 클라우드 기본 서비스·도메인·HTTPS 이해.
- **기술**: S3, CloudFront, Route53(또는 Cloudflare), ACM, IAM.
- **단계**: ① 정적 사이트(HTML) 준비 ② S3 버킷 생성(퍼블릭 차단 유지) ③ CloudFront + OAC로 S3 비공개 접근 ④ ACM 인증서 발급(us-east-1) ⑤ 도메인 연결 ⑥ 캐시 무효화와 캐시 정책 실험.
- **완성 기준**: HTTPS 도메인 접속, S3 직접 접근 차단, 캐시 히트 헤더 확인.
- **README 포인트**: S3를 퍼블릭으로 열지 않고 CloudFront OAC를 쓴 이유, 비용(거의 0원~월 수백 원, 도메인 별도).
- **비용 절감**: 도메인 없이 CloudFront 기본 도메인 사용 가능.

## 프로젝트 2. [★★☆☆☆] 3-tier 웹 서비스 수동 구축 후 문서화
- **목표**: VPC·서브넷·보안그룹·ALB·RDS 연결 감각.
- **기술**: VPC, EC2, ALB, ASG, RDS(또는 EC2 위 MySQL), Route53.
- **단계**: ① 2AZ VPC(퍼블릭/프라이빗) 설계 ② 앱 서버(간단한 Flask/Node) 프라이빗 배치 ③ ALB(퍼블릭)→앱→RDS(격리) ④ 보안그룹 체인 ⑤ ASG로 인스턴스 하나 종료해도 복구 확인 ⑥ SSM으로 접속.
- **완성 기준**: ALB DNS로 서비스, 인스턴스 종료 시 자동 복구, DB는 외부에서 접근 불가.
- **README**: 다이어그램, 보안그룹 표, 장애 테스트 결과.
- **비용 절감**: RDS 대신 t3.micro EC2 MySQL, NAT Gateway 대신 NAT 인스턴스 또는 VPC Endpoint, 실습 후 즉시 삭제(NAT GW/ALB는 시간 과금).

## 프로젝트 3. [★★☆☆☆] Docker 컨테이너화 + Compose 멀티 서비스
- **목표**: 이미지 최적화, 컨테이너 네트워킹/볼륨.
- **기술**: Docker, docker compose, Nginx, 앱 + DB + Redis, Trivy, ECR(선택).
- **단계**: ① 앱 Dockerfile ② 멀티스테이지·슬림 이미지 ③ 비루트 사용자·헬스체크 ④ compose로 웹/DB/캐시 ⑤ 볼륨으로 데이터 유지 ⑥ Trivy 스캔.
- **완성 기준**: `docker compose up` 한 줄로 동작, 이미지 크기 비교표, 취약점 HIGH 0개 또는 사유 기록.
- **README**: 이미지 크기·빌드 시간 개선 수치, 보안 조치.
- **비용**: 로컬, 무료.

## 프로젝트 4. [★★★☆☆] Terraform으로 3-tier 인프라 코드화
- **목표**: 프로젝트 2를 코드로 재현. 모듈/원격 state.
- **기술**: Terraform, S3 backend(+락), VPC 모듈, ALB/ASG/RDS, tflint, Checkov, Infracost.
- **단계**: ① backend 부트스트랩 ② VPC 모듈 ③ 앱/DB 모듈 ④ dev/prod 디렉터리 분리 ⑤ 변수·출력 정리 ⑥ Checkov로 보안 점검 ⑦ GitHub Actions에서 PR 시 plan.
- **완성 기준**: 빈 계정에서 `apply` 한 번으로 구성, `destroy`로 깨끗이 삭제, 보안 스캔 통과(예외는 사유 문서화).
- **README**: 모듈 구조도, 환경 분리 이유, 월 예상 비용(Infracost).
- **비용**: apply→검증→destroy 사이클로 몇 달러 미만.

## 프로젝트 5. [★★★☆☆] CI/CD 파이프라인 (GitHub Actions → AWS)
- **목표**: 코드 푸시부터 배포까지 자동화, OIDC.
- **기술**: GitHub Actions, Docker, ECR, ECS Fargate 또는 EC2, OIDC, Trivy, 슬랙 알림.
- **단계**: ① PR: 린트/테스트 ② main: 이미지 빌드 → 스캔 → ECR 푸시(커밋 SHA 태그) ③ 배포(ECS 서비스 업데이트) ④ 헬스체크 실패 시 자동 롤백 ⑤ prod 승인 환경 ⑥ 슬랙 결과 알림.
- **완성 기준**: 커밋 → 5~10분 내 자동 배포, 장기 AWS 키 없음, 실패 시 롤백 증명.
- **README**: 파이프라인 다이어그램, 평균 배포 시간, 롤백 시연 GIF.
- **비용 절감**: ECR 수명주기 정책, 서비스 야간 중지, EC2 단일 인스턴스로 대체 가능.

## 프로젝트 6. [★★★★☆] 쿠버네티스 + GitOps (ArgoCD) 배포
- **목표**: K8s 운영 기본기와 GitOps.
- **기술**: kind/k3s(로컬) 또는 EKS, Helm, ArgoCD, Ingress-nginx, cert-manager, HPA.
- **단계**: ① 앱 Helm 차트 ② 앱/매니페스트 저장소 분리 ③ ArgoCD App으로 동기화 ④ CI가 이미지 태그를 매니페스트 저장소에 PR ⑤ 롤링 업데이트·롤백 ⑥ HPA 부하 시연 ⑦ self-heal 시연(수동 변경 되돌림).
- **완성 기준**: Git 커밋만으로 배포·롤백, 클러스터 직접 수정 시 자동 복구.
- **README**: GitOps 흐름도, 환경별 values, 장애 시연 로그.
- **비용 절감**: 로컬 kind/k3s로 전부 가능(무료). EKS는 컨트롤 플레인 시간당 과금 → 하루 단위 실습 후 삭제.

## 프로젝트 7. [★★★★☆] 관측성 스택 (Prometheus + Grafana + Loki + 알림 + SLO)
- **목표**: 모니터링·로깅·알림 설계, SRE 감각.
- **기술**: kube-prometheus-stack, Loki, Alertmanager, 슬랙, k6, OpenTelemetry(선택).
- **단계**: ① 프로젝트 6 클러스터에 스택 설치 ② 앱 메트릭(RED) 노출 ③ 대시보드(서비스/노드/Pod) ④ SLO 99.5% 정의, 번 레이트 알림 ⑤ 로그→메트릭 연결(요청 ID) ⑥ 장애 주입(Pod kill, 지연, 5xx) ⑦ 포스트모템 2건 작성.
- **완성 기준**: 장애를 주입하면 5분 내 알림, Runbook 링크, 대시보드로 원인 도출 시연.
- **README**: SLI/SLO 정의, 알림 규칙 표, 포스트모템 링크.
- **비용**: 로컬 무료.

## 프로젝트 8. [★★★★☆] 보안 강화 멀티 계정/최소 권한 + 시크릿 관리
- **목표**: 실무형 보안 구조.
- **기술**: AWS Organizations(무료), IAM Identity Center, SCP, KMS, Secrets Manager/SSM, CloudTrail, GuardDuty(체험), Terraform, External Secrets/SOPS.
- **단계**: ① dev/prod/log 계정 분리 ② SSO 로그인, 장기 키 제거 ③ SCP로 리전 제한·루트 사용 차단 ④ 앱이 역할로 시크릿 조회 ⑤ CloudTrail 중앙 로그 계정 ⑥ 위험 구성 탐지(오픈 SG, 퍼블릭 S3) 자동 알림 ⑦ 키 노출 시나리오 대응 훈련 문서.
- **완성 기준**: 코드/CI에 장기 키·평문 비밀 없음, 위험 구성 시 알림 확인, 대응 절차서.
- **비용**: 대부분 무료/소액(Secrets Manager는 비밀당 월 소액, GuardDuty는 체험 기간).

## 프로젝트 9. [★★★★★] 고가용성 + 재해복구(DR) 및 비용 최적화 사례
- **목표**: 설계/트레이드오프, 숫자로 말하기.
- **기술**: 멀티 AZ, RDS 백업/복제, S3 교차 리전 복제, Route53 헬스체크 failover, Terraform, 비용 분석.
- **단계**: ① RTO/RPO 목표 정의 ② 파일럿 라이트 또는 웜 스탠바이 설계 ③ 리전 장애 가정 훈련(Game Day) ④ 복구 소요 시간 측정 ⑤ 같은 서비스의 비용 최적화(라이트사이징, Savings Plans 계산, 스토리지 수명주기) 전/후 비교 ⑥ ADR(설계 결정 기록) 작성.
- **완성 기준**: 복구 시간 측정값, 비용 전/후 수치, ADR 3개 이상.
- **비용 절감**: 설계·계산·짧은 실측 위주, 훈련 후 즉시 삭제.

## 프로젝트 10. [★★★★★] MLOps 플랫폼 미니 버전
- **목표**: ML 모델 학습→배포→모니터링 파이프라인과 GPU 인프라 이해.
- **기술**: MLflow, Airflow 또는 Argo Workflows/Kubeflow Pipelines, FastAPI/KServe, Docker, K8s, GitHub Actions, Evidently, Prometheus/Grafana, (선택) GPU/vLLM.
- **단계**: ① 데이터→학습→평가 파이프라인 ② MLflow 추적/레지스트리 ③ 임계치 통과 시 자동 컨테이너 빌드/배포 ④ 서빙 API 부하 테스트와 HPA ⑤ 드리프트 리포트 → 재학습 트리거 ⑥ (선택) GPU 활용률 대시보드, LLM 서빙 처리량 측정.
- **완성 기준**: 코드/데이터 변경 시 자동으로 학습→배포, 드리프트 알림, 모델 롤백 시연.
- **README**: ML 파이프라인 다이어그램, 모델 버전 관리 전략, 재현성 설명, 비용/GPU 사용 계획.
- **비용 절감**: CPU 모델/작은 데이터셋, 로컬 kind, GPU는 짧게(Spot, Colab/Kaggle 무료 GPU로 학습만 대체), LLM은 소형 모델.
